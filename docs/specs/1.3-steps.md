# Task 1.3 — Implementation steps

Breakdown of [1.3-sync-api.md](1.3-sync-api.md) into four steps. Details
(rules, JSON shapes, validation) live in the main spec; section, decision and
check numbers below refer to it. Each step ends with green `php artisan test`
and is committed separately after the file list is approved.

## Step 1 — Schema check and simulated external service

**Goal:** the database rejects a `synced` order without an external ID, and
the simulated external service answers deterministically.

**Scope:** D3 migration (§7); `OrderFactory::synced()` and the
`DataModelTest` fix (§9); `ExternalServiceResponse` and `FakeExternalService`
(§4). No service, no HTTP.

**Done when:**
- D3 rejects both invalid combinations (C10); migration rolls back and
  re-applies on `merchantops_test` (C17).
- Every row of the §4 decision table is covered, including `remaining = 0`
  and no simulation row (C13).
- 1.1 and 1.2 tests still pass.

## Step 2 — Sync service

**Goal:** one tested write path for attempts and the order summary.

**Scope:** `OrderSyncService` and `OrderAlreadySyncedException` (§5). Tests
call the service directly, no HTTP.

**Done when:**
- Scenarios C1–C4 pass at service level (C4 as an exception, no attempt
  written).
- Summary consistency C11 and atomicity C12 pass.
- `FakeExternalService` is the only class touching `simulated_failures`
  (R3, checked by review).

## Step 3 — Read API

**Goal:** an operator can list orders and open one with its history.

**Scope:** routes, `OrderController@index` and `@show`, the three resources
(§6.1–6.3). No write endpoints yet.

**Done when:**
- JSON shapes match §6.1 and §6.3; attempts newest first with the `id`
  tie-breaker (C5 with attempts created by the service).
- Status filter, `422` on an unknown status, pagination meta (C6).
- Unknown order ID → `404` (part of C9).

## Step 4 — Write API and documentation

**Goal:** the full scenario works over HTTP.

**Scope:** `OrderController@sync` with `409` rendering (§6.4),
`SimulatedFailureController` and `UpdateSimulatedFailureRequest`
(§6.5–6.6); README (Status, API, manual scenario); 1.2 spec Q4/Q7 references.

**Done when:**
- C1–C4 pass over HTTP; C7–C9 pass.
- Determinism grep (C14), full suite (C15), main DB untouched (C16).
- Migration applied to the main DB (C17).
- Manual scenario §11 run only if the user agrees (C18, R4).
