# Task 1.2 — Data model and migrations

Status: accepted (Q7 open, to be resolved in 1.3)
Depends on: 1.1 (infrastructure, `/api/health`)
Followed by: 1.3 (sync logic, controllers, API)

## 1. Goal

Create the persistence layer for order synchronization diagnostics: three
tables, PHP enums, Eloquent models, factories and a deterministic seeder.
After this task the database can hold orders, an append-only log of sync
attempts, and per-order settings for the simulated marketplace — but nothing
writes to them except the seeder and tests.

## 2. Scope

### In scope

- Enums in `backend/app/Enums/`: `SyncStatus`, `SyncErrorCode`,
  `AttemptTrigger`, `AttemptResult`.
- Migrations in `backend/database/migrations/` for `orders`, `sync_attempts`,
  `simulated_failures`, including constraints, foreign keys and indexes.
- Models in `backend/app/Models/`: `Order`, `SyncAttempt`, `SimulatedFailure`
  with relations and enum casts.
- Factories in `backend/database/factories/` for all three models.
- `DatabaseSeeder` producing a fixed, reproducible data set.
- Feature tests for constraints, relations, cascades and casts.

### Out of scope

- Sync logic (performing an attempt, consuming `remaining`, updating the
  denormalized fields on `orders`) — task 1.3.
- Controllers, routes, API resources, validation — task 1.3.
- Frontend changes.
- Authentication, users, queues, Redis or any other new technology.
- Restoring Laravel's default tables (`users`, `cache`, `jobs`, `sessions`).
  Cache and sessions stay on `file`, the queue stays on `sync`.

## 3. Enums

All enums are string-backed (`enum X: string`). Database columns store the
backing value.

### `SyncStatus`

| Case      | Value     | Meaning                                       |
|-----------|-----------|-----------------------------------------------|
| `Pending` | `pending` | Not yet synced, or awaiting a retry           |
| `Synced`  | `synced`  | Last attempt succeeded                        |
| `Failed`  | `failed`  | Last attempt failed                           |

### `AttemptTrigger`

| Case      | Value     | Meaning                                   |
|-----------|-----------|-------------------------------------------|
| `Initial` | `initial` | First attempt for the order               |
| `Retry`   | `retry`   | Any subsequent attempt                    |

### `AttemptResult`

| Case      | Value     |
|-----------|-----------|
| `Success` | `success` |
| `Failed`  | `failed`  |

### `SyncErrorCode`

Each case exposes `message(): string` and `retryable(): bool`. Both are
defined in code with a `match`, not in the database.

| Case               | Value               | Retryable | Message (proposed)                                  |
|--------------------|---------------------|-----------|-----------------------------------------------------|
| `Timeout`          | `timeout`           | yes       | Marketplace did not respond in time.                |
| `Unavailable`      | `unavailable`       | yes       | Marketplace is temporarily unavailable.             |
| `RateLimited`      | `rate_limited`      | yes       | Too many requests to the marketplace.               |
| `ValidationFailed` | `validation_failed` | no        | Marketplace rejected the order data.                |
| `Unauthorized`     | `unauthorized`      | no        | Marketplace credentials were rejected.              |

## 4. Tables

Conventions:

- Primary keys: `id bigint` (Laravel `id()`).
- Timestamps: `timestamptz` (`timestampsTz()` / `timestampTz()`), see Q3.
- Enum columns: `varchar` with a `CHECK` constraint listing allowed values
  (Laravel's `enum()` on PostgreSQL produces exactly this). Allowed values are
  written literally in the migration, not derived from `Enum::cases()`, so an
  old migration never changes when an enum grows (see R2).
- Money: integer minor units (`total_cents`), never float or decimal.

### 4.1 `orders`

Order data plus the current sync state, denormalized for fast listing.

| Column                 | Type           | Null | Default   | Constraints / notes                                  |
|------------------------|----------------|------|-----------|------------------------------------------------------|
| `id`                   | bigint         | no   | identity  | PK                                                   |
| `number`               | varchar(32)    | no   |           | `UNIQUE`; human-readable, e.g. `MO-0001`             |
| `customer_name`        | varchar(255)   | no   |           |                                                      |
| `total_cents`          | integer        | no   |           | `CHECK (total_cents >= 0)`                           |
| `currency`             | char(3)        | no   |           | ISO 4217, uppercase; `CHECK (currency ~ '^[A-Z]{3}$')` |
| `sync_status`          | varchar        | no   | `pending` | `CHECK IN (pending, synced, failed)`; indexed        |
| `marketplace_order_id` | varchar(64)    | yes  | `null`    | `UNIQUE`; set on successful sync; see Q4             |
| `last_error_code`      | varchar        | yes  | `null`    | `CHECK IN (<SyncErrorCode values>)`                  |
| `attempts_count`       | integer        | no   | `0`       | `CHECK (attempts_count >= 0)`                        |
| `last_attempt_at`      | timestamptz    | yes  | `null`    |                                                      |
| `created_at`           | timestamptz    | yes  |           |                                                      |
| `updated_at`           | timestamptz    | yes  |           |                                                      |

Indexes: `orders_number_unique`, `orders_marketplace_order_id_unique`,
`orders_sync_status_index`.

### 4.2 `sync_attempts`

Append-only log by convention: rows are inserted, never updated. Not enforced
in code or database (Q2).

| Column          | Type         | Null | Default | Constraints / notes                                   |
|-----------------|--------------|------|---------|-------------------------------------------------------|
| `id`            | bigint       | no   | identity| PK                                                    |
| `order_id`      | bigint       | no   |         | FK → `orders.id`, `ON DELETE CASCADE`                 |
| `trigger`       | varchar      | no   |         | `CHECK IN (initial, retry)`                           |
| `result`        | varchar      | no   |         | `CHECK IN (success, failed)`                          |
| `error_code`    | varchar      | yes  | `null`  | `CHECK IN (<SyncErrorCode values>)`                   |
| `error_message` | text         | yes  | `null`  | Snapshot of the message at attempt time               |
| `retryable`     | boolean      | yes  | `null`  | Snapshot of `retryable()` at attempt time             |
| `created_at`    | timestamptz  | no   | `now()` | No `updated_at` column                                |

Table-level consistency check:

```sql
CHECK (
  (result = 'success' AND error_code IS NULL AND error_message IS NULL AND retryable IS NULL)
  OR
  (result = 'failed'  AND error_code IS NOT NULL AND error_message IS NOT NULL AND retryable IS NOT NULL)
)
```

Indexes: composite `(order_id, created_at)` — covers the FK and the
"attempts of an order, newest first" query in 1.3.

`error_message` and `retryable` are stored, not computed, so that history stays
accurate if the enum's text or classification changes later.

### 4.3 `simulated_failures`

Per-order configuration of the simulated marketplace.

| Column       | Type         | Null | Default | Constraints / notes                                   |
|--------------|--------------|------|---------|-------------------------------------------------------|
| `id`         | bigint       | no   | identity| PK                                                    |
| `order_id`   | bigint       | no   |         | FK → `orders.id`, `ON DELETE CASCADE`; `UNIQUE`       |
| `error_code` | varchar      | no   |         | `CHECK IN (<SyncErrorCode values>)`                   |
| `remaining`  | integer      | yes  | `null`  | `null` = fail forever; `N` = fail N more times; `CHECK (remaining IS NULL OR remaining >= 0)` — see Q5 |
| `created_at` | timestamptz  | yes  |         |                                                       |
| `updated_at` | timestamptz  | yes  |         | `remaining` is decremented in 1.3                     |

Indexes: `simulated_failures_order_id_unique` (also serves the FK).

## 5. Relations and deletion rules

```
orders 1 ──< sync_attempts        (hasMany / belongsTo)
orders 1 ──o simulated_failures   (hasOne  / belongsTo)
```

| Model              | Relation                                   |
|--------------------|--------------------------------------------|
| `Order`            | `syncAttempts(): HasMany`                  |
| `Order`            | `simulatedFailure(): HasOne`               |
| `SyncAttempt`      | `order(): BelongsTo`                       |
| `SimulatedFailure` | `order(): BelongsTo`                       |

Deletion:

- Deleting an order deletes its attempts and its simulation at the database
  level (`ON DELETE CASCADE`), regardless of whether the delete goes through
  Eloquent.
- Child rows cannot exist without an order (`order_id NOT NULL`, FK enforced).
- `ON UPDATE` is left at the default; primary keys are never updated.
- No soft deletes.

## 6. Models

Common rules:

- `$fillable` lists the writable columns explicitly; no `$guarded = []`.
- Casts via the `casts(): array` method.
- Each model uses `HasFactory`.

| Model              | Casts                                                                                                   |
|--------------------|---------------------------------------------------------------------------------------------------------|
| `Order`            | `sync_status → SyncStatus`, `last_error_code → SyncErrorCode`, `total_cents → integer`, `attempts_count → integer`, `last_attempt_at → immutable_datetime` |
| `SyncAttempt`      | `trigger → AttemptTrigger`, `result → AttemptResult`, `error_code → SyncErrorCode`, `retryable → boolean`, `created_at → immutable_datetime` |
| `SimulatedFailure` | `error_code → SyncErrorCode`, `remaining → integer`                                                     |

`SyncAttempt` sets `const UPDATED_AT = null`.

## 7. Factories and seeder

Determinism is mandatory (project rule): no Faker, no `random_*`, no
`Str::random`, no `now()`-dependent values in seeded data.

### Factories

- `OrderFactory` takes values from a static counter, e.g.
  `number = sprintf('TEST-%04d', $n)`, `total_cents = 1000 * $n + 99`, so
  several orders get unique numbers. The `TEST-` prefix keeps factory numbers
  apart from the seeded `MO-` numbers. The counter is not reset between tests:
  tests must not rely on generated numbers or ids and pass values explicitly
  when they matter.
- Default state of `OrderFactory`: `sync_status = pending`, `attempts_count = 0`,
  `currency = EUR`, all sync fields `null`.
- Default state of `SyncAttemptFactory`: `trigger = initial`,
  `result = success`, error fields `null`.
- Default state of `SimulatedFailureFactory`: `error_code = timeout`,
  `remaining = null`.
- Child factories create their own order unless one is given (`for($order)`).
- `SyncAttemptFactory` states: `success()`, `failed(SyncErrorCode $code)`;
  `failed()` fills `error_message` and `retryable` from the enum.
- `SimulatedFailureFactory` states: `always(SyncErrorCode $code)`
  (`remaining = null`), `limited(SyncErrorCode $code, int $remaining)`. The
  name `times()` is taken by Laravel's `Factory::times()`.

### Seeder

`DatabaseSeeder` creates exactly 20 orders `MO-0001` … `MO-0020`, all
`pending`, no attempts, and these simulations:

| Order     | `error_code`        | `remaining` | Expected behaviour in 1.3          |
|-----------|---------------------|-------------|------------------------------------|
| `MO-0003` | `timeout`           | `1`         | Fails once, then succeeds on retry |
| `MO-0005` | `rate_limited`      | `2`         | Fails twice, then succeeds         |
| `MO-0007` | `unavailable`       | `null`      | Always fails, retryable            |
| `MO-0009` | `validation_failed` | `null`      | Always fails, not retryable        |
| `MO-0011` | `unauthorized`      | `null`      | Always fails, not retryable        |

Customer names come from a fixed in-code list. Currency is `EUR` for all
orders (Q6). The seeder sets numbers, names and totals explicitly and does not
depend on the factory counter. Running `migrate:fresh --seed` twice on the test
database produces identical rows (except timestamps); a second `db:seed`
without `fresh` fails on the unique `number`.

## 9. Open architectural questions

| #  | Question | Options | Recommendation | Status |
|----|----------|---------|----------------|--------|
| Q1 | How to store enum columns in PostgreSQL | (a) `varchar` + `CHECK`; (b) native `CREATE TYPE ... AS ENUM`; (c) plain `varchar`, validated only in PHP | (a): enforced by DB, easy to extend in a new migration, supported by Laravel's schema builder | Accepted: (a) |
| Q2 | How to enforce immutability of `sync_attempts` | (a) model guard: throw in `updating`/`deleting` events; (b) DB trigger rejecting `UPDATE`; (c) convention only | (a) for 1.2; note that it does not stop `DB::table()->update()`. Cascade delete from `orders` must keep working, so block only `UPDATE` | Accepted: (c) — no enforcement; only the 1.3 sync service writes attempts |
| Q3 | `timestamp` vs `timestamptz` | Laravel default `timestamps()` is without time zone | `timestamptz`, consistent with ISO 8601 output of `/api/health` | Accepted: `timestamptz` |
| Q4 | Constraints on `marketplace_order_id` | (a) `UNIQUE` (nullable); (b) `CHECK (sync_status <> 'synced' OR marketplace_order_id IS NOT NULL)`; (c) none | (a) now; defer (b) until 1.3 defines whether a resync can clear the id | Accepted: (a); (b) deferred to 1.3 |
| Q5 | What `remaining = 0` means | (a) allowed, means "exhausted, succeed"; (b) forbidden (`>= 1`), 1.3 deletes the row when it reaches zero | (a): keeps history of configured simulations visible; 1.3 must treat `0` as "no failure" | Accepted: (a) |
| Q6 | Single or multiple currencies | Single `EUR` vs mixed in seed | Keep the column, seed a single currency; no conversion logic anywhere | Accepted: single `EUR` |
| Q7 | Who keeps `orders` denormalized fields consistent with `sync_attempts` | (a) application service in 1.3 inside one transaction; (b) DB trigger | (a): logic stays in PHP and is testable; DB triggers are out of the agreed stack style | Open |
| Q8 | `error_message` length | `text` vs `varchar(255)` | `text` — messages may later include marketplace details | Accepted: `text` |

## 10. Risks

| #  | Risk | Impact | Mitigation |
|----|------|--------|------------|
| R1 | Denormalized fields on `orders` (`sync_status`, `last_error_code`, `attempts_count`, `last_attempt_at`) drift from `sync_attempts` | List shows wrong state | Single write path in 1.3 within a DB transaction; a consistency test in 1.3 |
| R2 | Migrations derive CHECK values from `Enum::cases()` | Adding an enum case silently changes an old migration; `migrate:fresh` and production schemas diverge | Hard-code values in migrations; add a new migration when an enum grows |
| R3 | Enum value added in PHP but not in DB CHECK | Inserts fail at runtime | Test A13 plus a test that inserts every enum case into its column |
| R4 | Tests hit the main database | Seed data destroyed | `phpunit.xml` uses `<server name="DB_DATABASE">merchantops_test`; existing test asserts the DB name; keep `RefreshDatabase` |
| R5 | Attempt rows are not protected from updates | Attempt history altered by mistake | Accepted (Q2): single write path in 1.3; revisit if it becomes a requirement |
| R6 | `artisan serve` runs with `--no-reload` | `.env` changes during the task are not picked up | Restart the `backend` container after editing `backend/.env` |
| R7 | `integer` overflow for `total_cents` (max ≈ 21.4M in currency units) | Large orders cannot be stored | Acceptable for a demo; switch to `bigint` if needed |
| R8 | `app/Models`, `database/migrations`, `database/factories` were removed during cleanup | Autoload or `migrate` paths missing | Recreate directories; run `composer dump-autoload` in the container if factories are not found |
