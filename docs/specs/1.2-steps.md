# Task 1.2 — Implementation steps

Breakdown of [1.2-data-model.md](1.2-data-model.md) into four steps. Details
(columns, values, constraints) live in the main spec; section and check
numbers below refer to it. Each step ends with green `php artisan test`.

## Step 1 — Enums

**Goal:** define the vocabulary of the data model in code.

**Scope:** `SyncStatus`, `SyncErrorCode`, `AttemptTrigger`, `AttemptResult`
in `backend/app/Enums/` (§3); `SyncErrorCode::message()` and `retryable()`;
unit test `SyncErrorCodeTest`. No database, no models.

**Done when:**
- Enum values match §3 exactly.
- `retryable()` is `true` only for `timeout`, `unavailable`, `rate_limited`;
  every case has a non-empty `message()` (A13).

## Step 2 — Migrations

**Goal:** make the database enforce the data model on its own.

**Scope:** three migrations (§4) with types, CHECK constraints, unique
indexes, `orders.sync_status` index, FKs with `ON DELETE CASCADE`. Enum
values hard-coded in migrations (R2). No models; tests use `DB::table()`.

**Done when:**
- `migrate:fresh` passes; `migrate:rollback` removes all three tables;
  `migrate` again passes (A1 without seed, A3, A4).
- Database rejects: duplicate `number`, second simulation per order, unknown
  enum value, negative `total_cents`, inconsistent attempt row, orphan child
  row (A5–A10).
- Deleting an order removes its attempts and simulation (A11).

## Step 3 — Models

**Goal:** give the application typed access to the tables.

**Scope:** `Order`, `SyncAttempt`, `SimulatedFailure` (§6): `$fillable`,
enum casts, relations (§5), `SyncAttempt::UPDATED_AT = null`, immutability
guard on `SyncAttempt` if Q2 is accepted. No factories yet — tests create
rows with `Model::create()`.

**Done when:**
- Reloaded models return enum instances for all enum columns (A12).
- `syncAttempts`, `simulatedFailure` and both `order` relations return the
  expected types (A14).
- `$order->delete()` through Eloquent cascades (A11 via model).

## Step 4 — Factories and seeder

**Goal:** provide reproducible data for tests and for task 1.3.

**Scope:** three factories with states (§7), `DatabaseSeeder` with 20 orders
and 5 simulations from the §7 table. Step 2–3 tests may switch to factories.
No Faker or other randomness.

**Done when:**
- `migrate:fresh --seed` passes; counts are `20` orders, `5` simulations,
  `0` attempts (A1, A2).
- Seeding twice gives identical rows except timestamps.
- Grep for randomness finds nothing (A15).
- Full suite is green, including `HealthCheckTest`; main DB untouched (A16,
  A17).
